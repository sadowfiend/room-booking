# Работа с AI: сессии реализации

Сжатая хронология сессий реализации. Источники: `raw/session-5-full.md` (`feat/server`), `raw/session-7-full.md` (`feat/ui`),
`raw/session-6-full.md` (интеграция в `main`). Время — UTC по логам. Расход — в `docs/ai-usage.md`.
Каждая ветка работала в своём worktree и в своей сессии Claude Code (Opus). Код писал `implementer` (Sonnet),
тесты — `test-writer` (Sonnet). Промпты для обеих сессий подготовила основная сессия.

## 3A. Сервер (`feat/server`, session-5, 16:47–16:59)
- **Запрос:** фазы 3A и 3C по PLAN; агенты только по имени; асинхронный `BookingRepository` с атомарными
  `create`/`update`; порядок «разбор → 404 → 422 → 409»; `await connection()` в GET; все ответы `no-store`.
  Остановиться после 3A и без ок пользователя не коммитить.
- **implementer:** репозиторий и in-memory-реализация (без `await` между чтением и записью), сервис, слой `http`,
  route handlers. Статус DONE.
  - **Решения агента** (приняты): неверная `date` в GET — 422 `INVALID_DATE`; форсированный конфликт работает и на PATCH,
    `conflicts` при этом может быть пустым; проверка `Content-Type` — `application/json` с параметрами.
  - **Сбой окружения:** первый `typecheck` упал на `LayoutProps` — в свежем worktree не было сгенерированных типов Next.
    После генерации типов проверка прошла; код не менялся.
- **test-writer:** 125 тестов сервера, всего 268, ошибок в реализации нет.
- **Проверки сессии:** typecheck, lint, test (268) зелёные; build: `/api/bookings` и `/api/bookings/[id]` — ƒ.
- **Итог:** по «ок» пользователя коммит `feat(server): bookings API with async in-memory repository`.

## 3C. Redis (`feat/server`, session-5, 16:59–17:29)
- **Запрос:** по PLAN 3C; `@upstash/redis` разрешён как обычная зависимость; имена env — списком, не одним именем.
- **implementer:**
  - `RedisBookingRepository`: CAS по версии даты. Чтение версии и брони, `findConflicts` в TypeScript,
    Lua-скрипт сравнивает версии и пишет. До 3 повторов, затем 409 (ложный 409 отмечен в комментарии к классу).
  - Фабрика: три пары env (`UPSTASH_*`, `KV_*`, свой префикс), при нескольких совпадениях — ошибка в лог и in-memory,
    без env — одно предупреждение. `/api/health` возвращает `{ ok, storage }`.
  - **Решение агента:** при постоянной конкуренции на `remove` после 3 попыток — 500, а не ложный 404.
  - **Не сделано:** `.env.example` закрыт правилом запрета в настройках прав, агент не смог его прочитать и записать.
    Вынес вопрос пользователю. Также сообщил о 5 уязвимостях high после `npm install`; `audit fix` не запускал.
- **test-writer:** 200 тестов сервера и API плюс 22 теста на настоящем Redis (пропускаются без `REDIS_TEST=1`):
  общий набор контрактных тестов репозитория, гонка «10 параллельных `create` — ровно один успех»,
  повтор при несовпадении версии, выбор хранилища по env, `/api/health`. Ошибок нет.
- **Проверки:** typecheck, lint зелёные; test — 343 и 22 пропущено; build: `/api/bookings`, `/api/bookings/[id]`,
  `/api/health` — ƒ.
- **Итог:** коммит `feat(server): Redis repository with version CAS and storage factory`; строки в `ai-usage.md`.
- **Эпизод с `.env.example`** (17:23–17:29): сессия не могла прочитать файл из-за правила прав, файла не было в
  worktree, а `.gitignore` (`.env*`) скрывал его от git. Сессия нашла это правило и предложила исключение.
  Пользователь остановил поиск: файл добавит сам в `main`. Закоммичена только правка `.gitignore`
  (`chore: allow .env.example`).
